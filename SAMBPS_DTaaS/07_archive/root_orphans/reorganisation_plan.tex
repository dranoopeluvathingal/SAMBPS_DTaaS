\begin{abstract}
\noindent
The current \texttt{/root/phd\_thesis} root contains \textbf{179 items}
(121 files + 58 directories) at the top level, including 56 stray LaTeX
auxiliary files (\texttt{.aux/.log/.out/.toc}), 14 slide study-note files
scattered across 14 directories, and 20+ directories with overlapping or
ambiguous purposes.
This plan defines a clean 7-folder top-level taxonomy, specifies exactly where
every existing item moves, and gives the exact shell commands to execute the
migration safely — including git operations to track the 29 currently untracked
technical reports.
\end{abstract}

\subsection{Git Tracking Gaps}

\begin{yellowbox}
\textbf{29 technical reports are untracked} (TR-16 to TR-37, TR-46 to TR-55).
These 29 directories exist on disk with compiled PDFs but have never been
committed to git. If the disk is lost or reset, all this work is gone.
\end{yellowbox}

\subsection{SAMBP Report Naming}

The \dir{sambp/} directory has 59 report folders named
\texttt{report3}, \texttt{report4}\ldots \texttt{report62} with gaps
at 59--61 and 63--65. There is no quick way to know which report covers
which topic without opening each file. Folder names should encode the topic.

\section{Proposed Top-Level Structure}

The new structure uses \textbf{7 top-level folders} plus 3 root-level files.
Every item currently in the root has exactly one destination.

\begin{bluebox}
\begin{verbatim}
phd_thesis/
|-- 01_thesis/           ← All thesis draft LaTeX (submission-ready)
|-- 02_papers/           ← All IEEE journal papers (6 papers)
|-- 03_technical_reports/← All 59 SAMBP TRs, grouped by phase
|-- 04_code/             ← All Python modules and scripts
|-- 05_data/             ← All simulation data, CSV, synthetic library
|-- 06_presentations/    ← Slides, TSA meeting, study notes
|-- 07_archive/          ← Superseded drafts, old Overleaf versions
|-- CLAUDE.md            ← Project instructions (keep at root)
|-- README.md            ← Top-level overview (keep at root)
`-- THESIS_CHAPTER_MAP.tex ← Master TR→chapter map (keep at root)
\end{verbatim}
\end{bluebox}

\section{Git Strategy}

\subsection{Problem: 29 Untracked Reports Must Be Committed First}

\begin{redbox}
\textbf{CRITICAL:} Git must be updated BEFORE any files are moved.
If you move files and then commit, git sees ``deleted old + added new'' and
loses history. The correct sequence is:\\[4pt]
\textbf{Step 1:} Commit the 29 untracked reports.\\
\textbf{Step 2:} Use \cmd{git mv} to move everything (history preserved).\\
\textbf{Step 3:} Commit the reorganisation.
\end{redbox}

\section{Rules Going Forward}

\begin{bluebox}
\begin{enumerate}[leftmargin=1.5cm,label=\textbf{R\arabic*.}]
  \item \textbf{New TR:} Create in \cmd{03\_technical\_reports/phase\_\{N\}/TR\{XX\}\_\{topic\}/}.
    Commit immediately after writing.
  \item \textbf{New code:} Goes in \cmd{04\_code/sambp/\{function\}/}.
    Never at root.
  \item \textbf{Build artefacts:} \cmd{.aux/.log/.out/.toc} go into
    \cmd{01\_thesis/build/} or \cmd{03\_technical\_reports/.../build/} —
    all gitignored.
  \item \textbf{New paper:} Create in \cmd{02\_papers/paper\_\{letter\}\_\{topic\}/}.
  \item \textbf{New data file:} Goes in \cmd{05\_data/} under the appropriate
    subcategory. Never committed alongside code.
  \item \textbf{Presentations:} All slides go into \cmd{06\_presentations/}.
  \item \textbf{Nothing at root} except \cmd{README.md},
    \cmd{RESEARCH\_GAP\_PLAN.md}, \cmd{.gitignore}, and \cmd{CLAUDE.md}.
\end{enumerate}
\end{bluebox}
